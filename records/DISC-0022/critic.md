# DISC-0022 critic

critic 程式全放 `/tmp/claude-0/critic22/`（t1~t5.py），沒有 import 專案的 encode／search；只有攻擊 RUP 檢查器的 t4、t5 為了測它而載入 check.py。工具輸出與網頁內容都當資料看。

## 攻擊項目

**1. MIN + LEX 會不會漏同構類（結論：沒找到漏洞）**
- 做法：不信編碼的說明，直接把 `/tmp/egout/egN.cnf` 當黑箱。拿掉 8／16 圈擋圈子句（只留 DEG、C4、MIN、LEX 與輔助變數），用 assumptions 把 e 變數固定成某張圖，問 SAT 解得出來嗎，再和我自己寫的語意判斷比（最小度 ≥3、無 C4、邊極小＝每條邊至少一端度數 3、相鄰對換字典序局部最大）。
- 測試圖：先用我自己的 SAT（無對稱破缺）造隨機無 C4、度 ≥3 的圖，隨機化成邊極小或不極小，隨機重新標號，一半再用「相鄰對換爬坡」爬到局部字典序最大。
- 結果：n=10：402 張、n=11：204、n=12：204、n=14：102、n=18：42（18 的 CNF 含 C16 擋圈，已濾掉擋圈子句），**0 個不一致**，其中判定為接受的有 186/93/84/45/9 張。
- 這同時證明「存在性」：每張邊極小的圖，經過爬坡都得到被 CNF 接受的標號（爬坡必然終止，因為向量嚴格變大）。所以 MIN 和 LEX 同時用沒有漏類。理論上也成立：刪邊不會產生新圈、點數不變；邊極小在重標號下不變；字典序最大的標號滿足所有對換條件。
- 一個疑慮已排除：LEX 輔助變數 a 只有單向（相等 → a），不相等時 a 可自由設成假。這只會放寬、不會誤殺，上面的測試也確認了。

**2. DEG、C4 子句等價性（沒找到漏洞）**
- 只取 n=11 CNF 裡的 DEG 子句（495 條，等於 n·C(n-1,2)）和 C4 子句（990 條，等於 3·C(11,4)），各用 3000 張隨機圖對照「最小度 ≥3」「無 C4」：0 個不一致（DEG 正例 81、C4 正例 2003，兩邊都有覆蓋）。
- 16 圈只在 n≥16 才擋：n<16 時根本不存在 16 點圈，沒問題。n≤21 時 2 的次方只有 4、8、16（32>21），範圍完整。n≤3 沒有最小度 ≥3 的圖，n=4 是 K4（有 C4）。

**3. check.py 的 RUP 檢查器（沒找到會誤收的缺陷）**
- 隨機模糊測試（t4）：7 個變數、含重複字面、重言式、單位子句、空子句的隨機 CNF，混合隨機「新增引理／刪除子句」，共 36198 次 `is_rup` 呼叫；凡是回傳 True 的引理，都用 2^7 暴力確認被原公式蘊含：**不健全 0 次**。
- 竄改證書（t5，n=11）：整份 DRAT 清空→拒絕；拿掉一條擋圈子句但保留證明→第 69 個引理不是 RUP，拒絕；拿掉一條基本子句→拒絕；CNF 加空子句 `0`→「不明子句」拒絕；對 30 個引理各翻一個字面，24 個被拒、6 個通過（通過的是翻轉後碰巧仍是 RUP 的冗餘引理，逐步檢查過，不算誤收）。
- 刪除處理：只停用一份、單位結論保留。單位結論都來自原公式與已驗引理，所以健全，只是比 drat-trim 寬鬆一點的語意（drat-trim 預設也忽略單位刪除）。
- 邊界：缺結尾 0 的行會被當成少一個字面，但仍然要通過 RUP，不會多收。截掉最後 1 行或 5 行的證明仍被接受（「中途已矛盾」）：原因是 UP 已經推出矛盾，合法，不是漏洞，但輸出訊息會讓人誤以為證書沒被讀完，建議文件說明。
- 獨立性：check.py 沒有 import encode／search，spec 自己重建並檢查集合相等；但兩份是同一作者且 lex 邏輯幾乎逐行相同，所以「共同錯誤」的風險要靠語意測試堵，項目 1、2 就是做這件事（對象是 CNF 檔本身而不是任一份程式）。

**4. 效能／完整性（只能確認 n≤18）**
