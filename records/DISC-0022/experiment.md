# DISC-0022 實驗

## 方法

- 程式：`discovery/egsat/`（說明 `docs/EGSAT.md`）。變數是 K_n 的每條邊；子句是「每點度 ≥ 3」（不用輔助變數）、「沒有 4 圈」（全部列出）、「邊極小」（每條邊至少一端度數恰好 3）、「相鄰對換字典序最大」（對稱破缺）。8 圈、16 圈太多，用 CEGAR：求解器給一張圖，找到 8 圈或 16 圈就把那個圈擋掉（每輪最多 50 個）再解，直到 UNSAT 或找到合格的圖。
- 為什麼剪枝不漏：反例一直刪邊、刪到不能再刪（再刪就有點度 < 3），還是反例（刪邊不會多出圈），點數不變，這時每條邊都有一端度數恰好 3；再取同構類裡上三角向量字典序最大的標號，它滿足所有相鄰對換的比較。
- 證書：UNSAT 時把最終公式寫成 CNF，用 CaDiCaL 1.9.5（PySAT）重新求解並輸出 DRAT。
- 獨立檢查（`check.py`，不 import 搜尋程式）：照文件規格自己重建基本子句、確認其餘子句都是 K_n 裡真的 4/8/16 圈，再用自寫的正向 RUP 檢查器驗 DRAT，必須推出空子句。

正面測試：拿掉 8 圈條件時，n = 9 UNSAT、n = 10 立刻找到沒有 4 圈、最小度 3 的圖（和已知「沒有 4 圈、最小度 ≥ 3 至少要 10 點」一致）。剪枝測試：n = 5、6、7 列舉所有解，和 networkx 圖譜裡每個「最小度 ≥ 3、邊極小」的同構類逐一比對，沒有漏。

結論：**n ≤ 17 沒有反例，有證書且被自寫檢查器驗過，每一步都在 `config/limits.json` 的 600 秒上限內。** n = 18（檢查 833 秒）、19（檢查 3249 秒，DRAT 77 MB）的證書也通過，但超過了上限（時間與 50 MB 輸出），事前沒有取得批准，所以原本列為「超出上限、待使用者追認」。**使用者 2026-11-23 已追認**（專案執行緒 19:03），所以主張改為 n ≤ 19。n = 20、21、22 只有求解器說 UNSAT（n = 22 求解 1377 秒，也超過上限），證書檢查已中止，不能算數。這次的計算沒有用 `discovery.limits.run_limited` 包起來，以後超過上限的計算要先申請。這只是重現，前人已到 40 點。

## 重現方式

```
pip install -r requirements.txt
# 每個 n 分開跑，n ≤ 17 每步都在 600 秒內
for n in 10 11 12 13 14 15 16 17; do
  python -m discovery.egsat.search $n --out OUT
  python -m discovery.egsat.check OUT $n
done
python -m pytest -q tests/test_egsat.py
```

CaDiCaL 與找圈的順序都是確定的，同一版 PySAT 重跑會得到同樣的 CNF。證書太大（n = 18 的 DRAT 約 31 MB、n = 21 約 300 MB）不放進 git，`data/egsat/summary.json` 記了每個 n 的 CNF、DRAT 的 SHA-256。
