## 攻擊項目

1. **A215944 的反例數算錯：應該是 211 個，不是 210 個。** 判定函式 `conjectures.a215944` 先呼叫 `_three_primes`，只要 n 有平方因數就直接回傳 None，也就是被當成「成立」。可是 `in_a215944` 這個成員判定是算重數的，所以兩邊對不上。10^10 以下有一項 5654273717 = 1093²·4733：它是 psp2，被較小的 psp2 1093² = 1194649 整除，而且屬於 b-file 的範圍。猜想的形式要求 p 整除 N 且 p³ ≤ N，所以只能 p = 1093；這時 A·B = 1093·4733，A、B 都要 ≥ 2p−1 = 2185，做不到。就算放寬到 m = 0（A = 1093），也要 4732 ≡ 0 (mod 1092)，但 4732 mod 1092 = 364。它也不是 5461 的倍數。所以它是反例，被漏掉了。「210」這個數字目前出現在 `paper/a215944-counterexample.md`、OEIS 草稿、`experiment.md`、`record.json`、`RESEARCH.md`，連 `tests/test_cxsearch.py:38` 也寫死了 210。最小反例 3048841 不受影響。
2. **用幾種不同讀法試著替 A215944 猜想解套，結果都救不回來**（`gochk_out.txt`）。定義域我試了兩種：「三個質因數（算重數）」共 798 項，和「任意個質因數、被較小 psp2 整除」共 3352 項。形式也試了兩種：m、k ≥ 1，以及 m、k ≥ 0（「自然數」包含 0）。p 可以是任何自然數，不必是質數；A、B 也可以是合數，我是列舉所有因數分解來判斷的。四種組合的最小反例都是 3048841，反例數分別是 211、211、254、254。寬定義域裡比 3048841 小、又寫不成這個形式的只有 158369 = 29·43·127，而它正好是 5461·29（k = 1）這個例外。另外，就算讓 m、k 取任意整數（包括負數），P 不管取 61、151、331 或任何合數因數，其餘兩個因數都不會 ≡ 1 (mod P−1)，所以 3048841 在每一種讀法下都是反例。
3. **用 b-file 對齊定義**：我獨立重算 10^7、10^8、10^9、10^10 以下的項數和總和，得到 65/220926779、155/4301817421、370/99483523854、798/1994907788036，和 S003 記下的數字一樣。3048841 是第 36 項。不過 b-file 的原始數字我沒辦法上網核對。

5. **A058128**：我用 Python 大整數檢查偶數 n ≤ 300，全部成立。草稿說「It fails for odd n >= 5」，我驗到 n ≤ 151，奇數裡只有 n = 3 成立，5^195 mod 195 = 125。但 paper 只舉了例子，沒有證明這是「全部」奇數都不成立。這句話其實可以證：要成立的話需要 S | n^(m/2) − 1，而 0 < n^(m/2) − 1 < S。只是 paper 沒寫這一步。

## 獨立重算

- **psp2 目錄，2^32 以下**：我用 C 寫了一個不篩質數的版本（`psp.c`）：對每個奇數 n 直接算 2^(n−1) mod n，通過的再用 12 個底的確定性 Miller–Rabin 排除質數。程式在 4 個 run_limited 進程裡跑，約 4.7 分鐘。結果 10403 項和 `psp2_1e10.txt.gz` 裡 ≤ 4294967295 的部分逐行完全相同。10^3 到 10^9 的計數是 3、22、78、245、750、2057、5597。
- **psp2 目錄，2^32 到 10^10**：我用 Go 寫的程式（以試除分解，用 bits.Mul64 做乘法取餘）確認 14884 項全部是合數的 psp2，不合格的 0 項。總數 14884 等於 A055550 的值，所以「每一項都是真的」加上「總數正確」，就推得清單完整。檔案 sha256 是 28a9b306…，和紀錄一致。
- **A215944**：最小反例 3048841，反例總數 **211**，詳見攻擊項目 1、2。
- **A321790、A218483、A058128**：見攻擊項目 5～7。
