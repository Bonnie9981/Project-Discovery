# DISC-0020 Critic（獨立審查）

結論：A362070 的反例 a(1715) = a(1716) = 91 **站得住**，我用兩套自己寫的程式和條目 Maxima 程式的逐行翻譯都重現了。找到兩個要修的地方（敘述過頭、10^10 掃描沒留紀錄），見文末「必修」。

我的程式都放在 scratchpad（照總控指示，除了本檔之外不改 repo），沒有 import 專案的任何模組：
- `mine.py`：照 %N 逐字算。m 從 1 開始，乘積對 n 取餘，乘出 rf(m, r)；Kempner 數直接乘階乘。
- `fast.py`：用 p 進賦值算。G(x) = Σ_{y≤x} v_p(y!) 用 ⌊y/q⌋ 求和的封閉式，每個 r 對 m 做二分搜尋；**不用**「e = 1 時只看最大質數」這個捷徑，所有質數冪都照通式算。
- `maxima_tr.py`：把條目的 Maxima 程式逐行翻成 Python。

## 攻擊項目

1. **照定義重算 DATA**：`mine.py` 算出的 n = 1..57 和 57 項 DATA 完全一樣。
2. **定義有沒有別種讀法**：
   - 如果 RisingFactorial 讀成下降階乘：t < k 時乘積是 0，所以 r ≥ 2 時 m_min 都是 1，會得到 a(18) = 6 + 5 = 11。條目 %e 寫的是 16，這個讀法排除。
   - 如果 t 從 0 開始：rf(0, k) = 0，同樣是錯的。
   - 如果 m 允許從 0 開始：只對 n = 1 有影響。
   - %e 寫出的 (1·2)·(2·3)·(3·4) 正是上升階乘 rf(t, r)。

   結論：找不到其他合理讀法能讓 1715 不成立。
3. **條目自己的 Maxima 程式**：逐行翻譯後算出 a(1715) = 91、a(1716) = 91，n = 2..19 也和 DATA 一致。這個程式有個小缺陷：如果 r! 已經能被 n 整除，內層迴圈一次都不跑，m 就會沿用上一個 r 的值。不過 r < K(n) 時 n 一定不整除 r!，所以不會觸發。
4. **Lean 敘述是否忠實**（`lean/Discovery/A362070Counter.lean`）：
   - `rf`、`P`、`fact` 的遞迴和定義一致。
   - `IsMMin` 要求 1 ≤ m、n | P k m，而且所有 1 ≤ j < m 都不整除，這就是「最小」。n 固定是 1715 或 1716，不會因為 n = 0 或 n = 1 而空成立。
   - `AValue` 裡的 f i 對應 r = i + 1，`sumTo f K` 是 f 0 + … + f(K−1)，也就是 r = 1..K，沒有差一。
   - `avalue_unique` 保證 AValue 是單值的，所以 `a362070_counterexample` 不是空話。
   - L1715、L1716 兩張表和 `mine.py` 算出的 m_min 序列逐項一樣。
5. **`decide` 會不會逾時**（未實測）：最大的數是 P 21 21 ≈ (41!)^21，大約一千多位數。乘法和取餘在 kernel 與 Meta 層都有 GMP 加速，遞迴深度只有 21，而且 repo 其他檔（CxBatch1、A294646Counter）也用同樣模式。我判斷應該能過，但本機沒有 Lean，**沒有實測**。
6. **scan.c 邏輯檢查**：
   - e = 1 的質數 p：v_p(P_r(m)) ≥ 1 等價於 m + r − 1 ≥ p，所以 m_min = max(1, p − r + 1)，而且隨 p 單調增加。因此只看最大的 e = 1 質數是對的。
   - K(n) 取各質數冪 Kempner 數的最大值，正確。
   - 收尾的封閉式 (P−r+1) + t(t+1)/2（t = P − r）正確。
   - `build` 裡 G 陣列的長度 2K+5 夠用；m 隨 r 不增，所以雙指標正確。
   - 每個 n 最多記 12 個質因數；10^10 以內最多只有 10 個相異質因數，夠用。
   - 比較用的是 128 位元，`%llu` 只在 dump 輸出時截斷，不影響判定。
7. **scan.c 實跑**：跑到 10^7，只有 HIT n = 1715，FIX 只有 1 和 16，1.2 秒。另外跑了 [9.99·10^9, 10^10+1] 這一段，0 個 HIT，1.4 秒。
8. **分段邊界**：程式裡的 `n>START` 條件表示，每一段的第一對 (START−1, START) 在該段內不會被比較，只能靠上一段的結尾掃到 N+1 來補。所以四段平行跑時，必須是下一段 START = 上一段 N + 1（或更小）才不漏。紀錄裡**沒有留下四段的參數和輸出**，無法查核（見必修 2）。
9. **A332786 程式**（`a332786.c`）：
   - 推理：q^t·S 是 q 整數，取模 q^(t+2e) 求賦值；m | a(m) 等價於對每個 q^e || m 都有 v_q(S) ≥ e。這個推理正確。
   - 提早 break 時 weak = 0，之後不會再用到沒分解完的 r，正確。
   - 我另外用 Fraction 精確算到 m ≤ 3000（原紀錄只對到 600）：合數裡只有 49 滿足 m | a(m)，沒有任何合數滿足 m^2 | a(m)，和 C 程式輸出一致。
