# DISC-0018 Critic 審查

審查者：Critic agent（獨立），2026-11-23。原始輸出放在 scratchpad，沒有放進 repo。

## 攻擊項目

1. **Lean 敘述和 OEIS 定義對得上嗎**：對得上。
   - A231897：`∃ m, wt (m*m) = n` 就是「找得到 m」，也就是「不會是 −1」。`wt` 和 `Nat.toDigits 2` 數出來的 1 個數，在 n < 2000 全部相同（我用 `#eval` 查過）。
   - A215461/A215462：條目 DATA 的 a(5)=0 只有在兩個加數都限定為奇數時才成立（不然 10 = 2 + 8 也會算進去），所以 Lean 加上 `% 2 = 1` 是對的。1 在 `NonPrime` 裡算非質數，和條目一致。「有序」只影響計數，不影響「至少一種拆法」。我用自己的 C 程式按定義直接計數，結果和 DATA 逐項相同，所以 offset 0 和「拆的是 2n」都沒問題。
   - 缺口（不影響結論）：Lean 只證了「存在一種拆法」，「存在一種拆法 ⇒ a(n) ≥ 1」這一步是用文字說明的，沒有形式化。proof.md 已經寫明這一點。
2. **編譯和公理**：Lean 4.15.0 跑 `lean NeverEasy.lean`，2.3 秒通過。原始檔裡找不到 sorry、admit、axiom、native_decide、extern、unsafe（只有註解裡出現 native_decide 這個字）。`#print axioms` 顯示三個主定理只用到 `propext` 和 `Quot.sound`。這個檔案也有被 `Discovery.lean` import，所以 CI 的 AxiomCheck 會檢查到它。
3. **改壞測試（確認證明不是空的）**：下面 7 種改法**全部**編譯失敗，符合預期。
   - n 的下限 19 改成 18、5 改成 4（n=19、n=5 本來就是反例）
   - 證人 9 改成 11、35 改成 37
   - 質數 7 改成 9
   - 因數 3 改成 1
   - `wt` 的定義多加 1
4. **紙上證明逐步檢查**：
   - H2：2n ≡ 2 (mod 6) 且 2n ≥ 40 時，最小的是 44。三種情況下第二個加數 ≡ 3 (mod 6) 且 ≥ 9，正確。
   - H3：2n−3、2n−5、2n−7 是連續三個奇數，所以恰好一個是 3 的倍數；最小的情況是 16−7 = 9 和 14−5 = 9，正確。
   - H1：一般的 a 正確。但 a = 0 時寫法裡會出現 2^(−1)，要另外處理（Lean 用 `cases` 處理了）。
5. **獨立重算**：用 C 寫了一支程式（自己做篩法，直接數拆法，沒有用卷積），也用一段新的 Python 做檢查。
   - A215461 的 74 項、A215462 的 80 項，都和 verify.py 裡的 DATA 相同。
   - 掃 n < 2,000,000（比原紀錄的 200,000 大 10 倍）：A215461 的 0 只出現在 n = 0、1、5；A215462 的 0 只出現在 n = 0、2、3、4、6、7、10、16、19。
   - A231897 的前 25 項用 popcount 暴力搜尋，全部相同。
   - wt((2^a−1)^2) = a 對 a ≤ 20000 都成立。
6. **說法有沒有誇大**：說「習題程度，不新」是誠實的。A215462 就是 AIME 1984 第 14 題（答案 38，就算 1 也算非質數，38 = 1 + 37 仍然拆不出來，和 a(19)=0 一致）。

## 結論
