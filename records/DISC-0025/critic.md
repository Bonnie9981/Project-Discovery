## 建議

1. **共用 RUP 檢查器。** 證書信任基底是 `discovery/egsat/check.py` 的自寫 RUP（DISC-0022 審過）。它不是 drat-trim。建議在 n = 8 的小證書上，再用 drat-trim 或 CaDiCaL 自帶的檢查器交叉驗一次。若環境沒有這些工具，就在 literature 或 proof 註明「未交叉驗」。
2. **check.py 末尾的 `r.propagate(0) or setattr(r, "inconsistent", True)` 寫法難讀。** 我試過它：n = 4 的空 DRAT 能通過，被截斷的 DRAT 會被拒，所以行為正確。建議加註解。
3. **P、C 見證的格式檢查可以更嚴。** C 的見證邊不要求是候選圖裡的邊，也不要求排序過。這不影響正確性，因為任何 |C| ≤ 2k 的 C 都能導出合法子句。proof.md 可以寫明這點，讓審查者不用重新推導。
4. **LEX 和 check.py 的重建與 search.py 長得很像**（同一個人寫、同一構造）。「逐條比對」能擋實作筆誤，但擋不住「構造本身的想法錯」。LEX 的正確性靠 n ≤ 6 圖譜測試加我下面的 canon 抽查。若想更強，可把圖譜測試延伸到 n = 7（1044 個圖，很快）。

## 攻擊項目

1. **INT（刪不在三角形裡的邊）。** 這種邊不影響任何三角形，所以 ν、τ 都不變，且刪邊後孤立點只是補點。不會漏反例。
2. **LEX 相容 INT。** 「每條邊都在三角形裡」在重新標號下不變，所以取同構類中字典序最大者仍滿足 INT。相鄰對換條件是字典序最大者的必要條件，所以是允許的剪枝。輔助變數 eq 只用單向蘊涵（相等 → eq 為真）。若 u 與 w 不等，solver 可自由選 eq 為假，所以可滿足性不受影響。
3. **kmax。** m ≤ C(n,2)，τ ≤ ⌊m/2⌋（二部子圖論證），所以反例需要 2k+1 ≤ ⌊n(n−1)/4⌋。代入 n = 8 得 k ≤ 6，n = 9 得 k ≤ 8，n = 10 得 k ≤ 10，都和實際跑的範圍一致。k = 0 沒有三角形，排除正確。孤立點論證正確，所以 n 點涵蓋 ≤ n 點。
4. **P 擋子句。** 若候選圖含 k+1 個邊互斥三角形，則 ν ≥ k+1。任何含這些邊的圖都不滿足 ν ≤ k，所以子句（這些邊不全在）不會誤殺反例。
5. **C 擋子句。** 反例的 τ ≥ 2k+1，所以對任何 |C| ≤ 2k，反例圖一定有不碰 C 的三角形。子句（至少一個不碰 C 的三角形存在）不會誤殺。若 C 不是候選圖的覆蓋，該 C 的子句也依然合法。
6. **check.py 是否獨立於 search.py。** 確認只 import `discovery.egsat.check` 的 RUP 和 read_cnf，沒有 import search。它自己重建 TRI、INT、LEX，並逐條比對 CNF 前段。
7. **竄改測試（我自己做的，n = 8、k = 3）。** 結果如下。
   - 刪掉 DRAT 中間大量引理：被拒（第 5 個引理不是 RUP）。
   - DRAT 清空：被拒（證明沒推出空子句）。
   - DRAT 只寫 `0`：被拒（第 0 個引理不是 RUP）。
   - 從 CNF 刪一條基本子句：被拒（基本子句不符）。
   - 重跑 `python -m pytest -q tests/test_tuzasat.py`：5 個通過。
8. **範圍聲明。** 我檢查了 record.json、experiment.md、literature.md、RESEARCH.md 和 summary.json 的說法：n ≤ 9 有證書，n = 10 只有 k ≤ 3 有證書，並且都寫了不宣稱新。novelty 狀態是 NO_MATCH_IN_SCOPE，附註說很可能有人做過，措辭誠實。唯一的小問題是上面「必修」第 3 點。
