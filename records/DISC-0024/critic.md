# DISC-0024 Critic 報告

## 攻擊項目

1. **INT（刪掉不在三角形裡的邊）：** 不在三角形裡的邊對 ν、τ 都沒有貢獻，刪掉後圖仍是同樣 (ν, τ) 的反例，所以可以假設每條邊都在三角形裡。論證成立。結果：沒找到漏洞。
2. **LEX 與 INT 相容：** INT 是同構不變的性質，所以「同構類裡字典序最大的標號」仍滿足 INT。我實際跑了：n=7，38 張隨機的「每條邊都在三角形裡」的圖，窮舉 7! 種標號取字典序最大者，用 `check.spec(7)` 的基本子句加假設驗證，38 張全被接受，0 張被拒。結果：LEX 沒有誤殺。（原本的測試只到 n≤6，這是補到 n=7。）
3. **k 範圍 1..kmax(n)：** 任何圖有至少 ⌈m/2⌉ 條邊的二部子圖，所以 τ ≤ m − maxcut ≤ ⌊m/2⌋ ≤ ⌊n(n−1)/4⌋。反例需 2k+1 ≤ 此值。我手算 kmax：n=4→1、5→2、6→3、7→4、8→6、9→8、10→10，和 summary.json 的 k 範圍一致（n=9 為 1..8）。k=0 沒有三角形、τ=0，不可能是反例。結果：成立。
4. **孤立點涵蓋較小 n：** 補孤立點不改變 ν、τ，也不破壞 INT（孤立點沒有邊）。LEX 取最大標號即可。成立。
5. **P 擋子句：** 子句是 k+1 個邊互斥三角形的 3(k+1) 條邊的負字面。任何含這些邊的圖 ν ≥ k+1，不滿足 ν ≤ k，所以擋掉的都不是反例。合法。
6. **C 擋子句：** C 是 ≤ 2k 條邊。若所有不碰 C 的三角形都不存在，則 C（的子集）覆蓋所有三角形，τ ≤ 2k，不是反例。子句「至少一個不碰 C 的三角形變數為真」合法。C 不必是候選圖的子集，不影響合法性。
7. **check.py 是否獨立驗 P、C：** 是。`check.py` 只 import `discovery.egsat.check` 的 `RUP`、`read_cnf`；基本子句自己重建並逐條比對（排序後）；P 檢查 k+1 個互異三角形兩兩無共用邊且子句集合剛好等於負字面；C 檢查 |C| ≤ 2k 且子句剛好是不碰 C 的三角形。結果：獨立性足夠。**但** TRI/INT/LEX 的建構在 search.py 和 check.py 是同一個人寫的同一個構造（check.py 的 LEX 幾乎逐行對應），所以「LEX 寫錯」是共同失誤風險；只靠 n≤6 圖譜測試加上我補的 n=7 抽樣擋住。
8. **證書重現：** 我重跑 `search 8 --out /tmp/critic24`，`check` k=1..6 全過。n=8 k=3 的 CNF、DRAT 的 SHA-256 和 summary.json 完全相同（edc18a74…、9d43eb7a…）。
