## 攻擊項目

### 1. C02（H1）：Lean 敘述和英文 H1 是否完全一致

- **做了什麼：** 逐字比對 `RadSigmaIff.lean:335-339` 和 hypotheses.md 的 H1。再查 `rad` 的定義（`RadSigma.lean:22`，`∏ p ∈ n.primeFactors, p`）、`σ` 的來源（`open ArithmeticFunction`，這是 Mathlib 的 scoped 記號，代表 `ArithmeticFunction.sigma`），也用 grep 確認三個檔案裡沒有自訂的 notation、instance、axiom 或 `set_option`。
- **結果：** 一致。唯一的前提是 `0 < n`，對應原文的 n ≥ 1，不是空洞前提。n ≥ 1 時 σ(n) ≥ 1，所以 `rad` 只會作用在正整數上，`rad 0 = 1` 這個怪處不會被用到。`∃ a p, n = 2^a * p` 裡因為有 `Odd p`，a 必定等於 v₂(n)，不會有「選錯 a」的漏洞。`2^(a+1) - 1` 是自然數減法，不會截斷。
- **邊界情況（逐一手算，也和程式結果核對）：**
  - n = 1：σ = 1，兩邊都是 1；屬於第一種情形。
  - n = 2：rad(σ 2) = rad 3 = 3 = σ(2)；屬於第一種情形。
  - p = 3：p + 1 = 4 不是無平方因子，而且 3 ∤ 4 這條也只是巧合地成立，所以第二種情形會被排除。例如 n = 24：rad(σ 24) = rad 60 = 30，σ(rad 24) = σ 6 = 12，不是解，和右側一致。
  - a = 1：n = 2p 由第一種情形涵蓋。反方向的證明用 `-` 丟掉了 `3 ≤ a`，所以確實沒有用到這個條件。
- **條件是否多餘（實際跑過）：**
  - 把 `Odd p` 和 `3 ≤ a` 拿掉：n ≤ 2·10⁵ 仍然 0 不符，和 proof.md 的說法一致。
  - **只拿掉 `Odd a`**（保留 a ≥ 3）：會出現 10 個不符，第一個是 **n = 976 = 2⁴·61**。這時 rad(31) = 31 整除 3·62，62 無平方因子，3 ∤ 62，所以右側成立。但 σ(976) = 31·62 = 2·31²，rad = 62，而 σ(rad 976) = σ(122) = 186，左側不成立。
  - 結論：`Odd a` 是必要條件，Lean 敘述有寫上，正確。

### 2. 是否已知或近乎平凡

- **反方向**只是直接計算：rad n = 2p，σ(2p) = 3(p+1)，σ(n) = (2^{a+1} − 1)(p+1)。
- **正方向**用一個標準的 Zsigmondy 論證就能完成，可以寫成教科書習題的長度：
  - 由 `odd_prime_factor_unique`，n = 2^a·p^b。
  - b 偶數時，σ(2^a)·σ(p^b) 是奇數，但 σ(rad n) 有 p+1 這個偶數因子，矛盾。
  - b 奇數且 ≥ 3 時，令 k = b + 1 ≥ 4。Zsigmondy 給出一個本原質因數 q ∣ p^k − 1，而且 q ∤ p² − 1（p 是奇數，所以不在 (2,6) 的例外裡）。q 整除 σ(p^b)，但 q 必須整除 3(p+1)。q = 3 不可能：若 3 ∤ p² − 1，則 p = 3，但 3 ∤ 3^k − 1。所以矛盾。
  - DISC-0006 的 critic 已經指出這一點，只是改用 LTE 而不用 Zsigmondy。literature.md **沒有提到 Zsigmondy**，也沒有把「這是 A065301 加上一個標準初等論證」寫進新穎性評估。
- **建議：**
  - 新穎性維持 `NO_MATCH_IN_SCOPE`，但等級要註明「習題等級的完整刻畫」，價值主要在 Lean 形式化。
  - 第二種情形的解在 a = 7 也有：n = 413312 = 2⁷·3229 和 935552 = 2⁷·7309。這和 DISC-0004「a ∈ {3,5,7}」的觀察一致。

### 3. R-003 試點（H3）

**3a. 非平凡過濾器 `nontrivial`**

- **做了什麼：** 讀邏輯。過濾條件是 `not all(any(G ∈ {n, 1}) for each class)`。
- **結果：** 某一類是線性、另一類不是的混合線索**會被保留**，例如規則 26：偶數類是 v₂pow，奇數類是常數 0，被列為非平凡。這部分正確。
- `search()` 在第一個整體擬合成功的模數就 `break`。如果 m = 1 已經有線性公式整體擬合，那個量本來就是 w 的線性函數，限制到更細的剩餘類仍然是線性，所以不會漏掉非平凡的東西。這一點無害。

**3b. 「所有剩餘類都要擬合」的要求會丟掉線索（必修 M1）**

- **做了什麼：** 用我自己的 (T,P) 資料（w ≤ 22，和 repo 的 `scan` 0 不符），對每個鏡像代表、每個量、m ∈ {1,2,4} 逐類呼叫 `am.fits`，找出「有非線性公式的類」和「完全擬合不到的類」同時存在的情形。
- **結果：** 有 **24 組**，全部被 `search()` 丟掉。幾個例子：
  - **(90, P, m=2)：奇數類 P = 2^{sord₂(w)} − 1**，偶數類擬合不到。這正是 Martin–Odlyzko–Wolfram 的已知結果，連它都被丟掉了。165 的情形相同。
  - (22, T, m=4)：w ≡ 0 和 w ≡ 3 (mod 4) 這兩類是 v₂pow 型，其餘兩類擬合不到。
  - (126, T, m=2)：奇數類是 v₂pow((w+1)/2)。
  - (218, T, m=2)：偶數類是 v₂pow(w/2)。
  - (150, P, m=4)、(105, P, m=4)、(18, P, m=4)、(26, P, m=4) 等：都是 2^{sord₂} − 1 型。
  - 涉及的規則還有 122、129、161、182、146、154、167。
- **影響：**
  - 這些線索很可能也都能化約到規則 90／150 家族（例如 22、126、218 在無限線上的單一種子圖樣就是 Sierpinski 三角形）。但在環上，奇數寬度會繞回來碰撞，所以這不是自動成立的，也**沒有人檢查過**。
  - 另外，**P 這一側沒有任何非平凡線索**。原因不是 P 裡沒有算術結構，而是偶數寬度那一類無法用單一個 G 表達。
  - 所以 H3 的負面結論只能說成「在『所有剩餘類都要擬合』這個限制下」。
