# A321790 程式說明（高二版）

## 共用的工具：反例搜尋器 `discovery/cxsearch/`

這個結果是用專案自己寫的「反例搜尋器」找到 / 檢查的。它的做法：

1. **先建一份清單**：10^10 以下所有以 2 為底的偽質數（psp2），共 14884 個，存在 `data/cx/psp2_1e10.txt.gz`。這份清單是用 C 程式 `discovery/cxsearch/psp2.c` 產生的：先用篩法把質數劃掉，剩下的奇數 n 用快速冪檢查 2^(n−1) 除以 n 是否餘 1。
2. **檢查清單對不對**：`catalog.check` 用 Python 重新驗證每一個都是 psp2，並且和 OEIS 上的已知個數（A055550：10^3 以下 3 個、10^4 以下 22 個、……、10^10 以下 14884 個）逐一比對。
3. **每個猜想寫成一個檢查函數**（在 `discovery/cxsearch/conjectures.py`），對清單上每個數跑一次，列出不符合的。

`discovery/cxsearch/numth.py` 是共用的數論小工具：判斷質數（Miller–Rabin 測試，在 3.3 × 10^24 以下保證正確）、因數分解（Pollard rho 方法）等。

## 怎麼自己跑

1. 裝 Python 3（python.org，安裝時勾「Add Python to PATH」）。
2. 到 https://github.com/Bonnie9981/Project-Discovery 按「Code」→「Download ZIP」，解壓縮。
3. 在解壓縮的資料夾（看得到 `discovery`、`data` 這些資料夾的那一層）開終端機，輸入下面「指令」那一行。整個跑完大約幾秒到十幾秒。

**指令（兩個）：**

```
python -m discovery.cxsearch scan A321790
python results\A321790\code\struct.py 100000
```

第一個的結果是 `"checked": 14884, "failures": 0`：10^10 以下的 psp2 裡，半質數都沒有違反猜想。

第二個（結構搜尋）p ≤ 100000 要跑一段時間（幾分鐘以上）；可以先用小一點的數字試，例如 `struct.py 3000`，結果應該是 `p <= 3000: G > 1 for 0 primes; hits []`，意思是沒有任何 p 留下可能的 q。

## 檢查函數在做什麼（`conjectures.py` 的 `a321790`）

1. 因數分解 k，不是剛好兩個質因數（半質數）就跳過。
2. 取最小質因數 p。
3. 從 a = 3 開始，一直試 `pow(a, k-1, k) == 1`（a 還騙得過 k）就加 1，直到騙不過或 a 到達 p。
4. 如果一直到 a = p 都騙得過（最小破底 ≥ p），就是反例，記下來。

## struct.py 在做什麼

對每個質數 p ≤ P：

- 先令 G = 2^(p−1) − 1。
- 對每個比 p 小的奇質數 a，把 G 換成 G 和 a^(p−1) − 1 的最大公因數（`math.gcd`）。技巧：`pow(a, p - 1, G) - 1` 是 a^(p−1) − 1 除以 G 的餘數，和 G 的最大公因數不變，但數字小很多，算得快。
- 把 G 裡 p 的因數除掉。如果 G 還大於 1，就把 G 分解，看有沒有 q > p 且 q − 1 是 p − 1 的倍數，有就是「可能的反例」。

證明說明裡解釋了為什麼反例 k = p × q 的 q 一定要整除這個 G。p ≤ 10^5 時 G 全部變成 1，所以沒有反例。

## 「?」= 873181 自己驗證（只要 Python）

```python
661 * 1321                     # 873181
k = 873181
pow(2, k-1, k)                 # 1 → psp2
[pow(a, k-1, k) for a in (3, 4, 5, 6, 7)]   # 前四個是 1，7 不是 1 → 最小破底是 7
```

注意這只驗證了「873181 的最小破底是 7」；「它是最小破底 7 的裡面最小的」要靠清單逐一檢查（上面那個 scan 指令裡有算）。
