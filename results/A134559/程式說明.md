# A134559 程式說明（高二版）

## 這些程式在算什麼

三種互相獨立的算法，都在算 b_n(k)、P(n) 和 gcd(P(n), n)：

| 檔案 | 語言 | 方法 |
|---|---|---|
| `code/chk134559.py` | Python | 用「n − k 的因數中大於 k 的總和」這個形式，重算三個反例 |
| `code/a134559.c` | C | 照「n 除以 u 餘 k」的原始定義，掃 n ≤ 1.5 × 10^5 |
| `code/antidiagonal.c` | C | 審查員另寫：用遞推公式一路推，掃到 3 × 10^5 |

（都在 `results/A134559/` 底下。另外 `python -m discovery.cxsearch scan A134559 --nmax 5000` 是搜尋器裡登記的版本。）

## 最簡單的一支：chk134559.py（你自己一定可以跑）

只要 Python 3：

```
python results\A134559\code\chk134559.py
```

輸出：

```
4934 gcd= 4934 k with p|b: [(134, 14802)]
6998 gcd= 6998 k with p|b: [(329, 10497)]
11114 gcd= 11114 k with p|b: [(106, 22228)]
```

意思是：n = 4934 時 gcd(P(n), n) = 4934（不是 2），而 k = 134 那一項 14802 是 2467 的倍數。另外兩個（6997、11113 的反例）也一樣。

**程式逐行說明：**

- `T(n, k)`：n 的因數中 ≥ k 的總和。`range(k, n+1)` 從 k 試到 n，`n % d == 0` 表示 d 是因數。
- `P_factors(n)`：列出所有 b_n(k) = T(n−k, k+1)，k = 0 到 ⌈n/2⌉ − 1（Python 的 `(n+1)//2` 就是 ⌈n/2⌉）。
- 對每個 n：找出哪些 b 是 p = n/2 的倍數，並把全部乘起來算 gcd。

## a134559.c：照原始定義掃

- `gP(n)`：對 u = 1 到 n，算 r = n 除以 u 的餘數，如果 r < ⌈n/2⌉ 就把 u 加到 b[r]。這完全照定義。然後把所有 b[k] 乘起來，但每乘一次就除以 n 取餘數（只需要知道 P(n) 和 n 的 gcd，而 gcd(P, n) = gcd(P 除以 n 的餘數, n)），避免數字爆掉。
- 主迴圈：對每個 n，檢查 (*) 成不成立（sat），以及 n 是不是 A005383 的成員（inA：n 是質數、n > 5、(n+1)/2 是質數）。兩者不一致就印出 MISMATCH。
- 跑法（需要 C 編譯器）：`gcc -O2 -o a134559 a134559.c` 然後 `./a134559 150000`，約 1 分鐘。結果：MISMATCH 只有那 7 個，而且全部是「在 A005383 裡但不滿足 (*)」，沒有反方向的。

## antidiagonal.c：審查員的第三種方法

不重新加總，而是用一個遞推關係從 n 推到 n+1：

> b_{n+1}(k+1) = b_n(k) − (k+1)·[若 (k+1) 整除 (n−k) 則為 1，否則為 0]，b_n(0) = n 的因數和

這和前兩種算法完全不同，速度也快很多，所以能掃到 3 × 10^5。它也印出 b_4934(134) = 14802、b_4934(0) = 7404 對答案。

## 不用程式也能自己驗證

- 手算 n = 13 的 b_13（證明說明第一步）。
- 用計算機加總：150 + 160 + 192 + 200 + 240 + 300 + 320 + 400 + 480 + 600 + 800 + 960 + 1200 + 1600 + 2400 + 4800 = 14802，再除以 2467 = 6。
- 4800 的因數裡，比 134 小一點的是 120，下一個是 150，所以清單從 150 開始。
