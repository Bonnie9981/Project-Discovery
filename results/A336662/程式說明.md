# A336662、A189722、A337353 程式說明（高二版）

> 依據：`results/A336662/code/check_a336662.py`、`records/DISC-0032/experiment.md`。輸出都實際跑過。

## 程式在算什麼

1. **三種暴力列舉**（用回溯法一步一步走，碰到不合規定就退回）：
   - `always_turn(m)`：一直轉彎的自避路徑，第一步向東、第一個轉彎向左（A189722）。
   - `manhattan_nocontact(k)`：Manhattan 格子上自避、沒有接觸的路徑（A336662）。`manhattan_ok` 判斷某個路口能不能往某個方向走。
   - `no_repeat_dir(n)`：方格上自避、不連續兩步同方向的路徑（A337353）。
   三個函式各寫各的，然後檢查 A336662(k) = 2·A189722(k+1)、A337353(n) = 4·A336662(n−1) = 8·A189722(n)，並確認原公式 A337353(1) = 4·A336662(1) 不成立。
2. **中點對應（`midpoint_check`）**：把 m ≤ 16 的所有正規化一直轉彎路徑（自避和不自避都算，共 32767 條）都做一次「取中點、轉 45 度」，檢查得到的 q 從原點向東出發、每一步都符合 Manhattan 格子的單行道方向，而且「原路徑自避 ⇔ q 自避且沒有接觸」。
3. **OEIS 資料**：三條條目存的所有項都拿來比；關係式在條目存的全部項上也檢查（k ≤ 38、n ≤ 39）。

## 怎麼跑

在 repo 根目錄：

```
python results/A336662/code/check_a336662.py 16
```

約 7 秒，輸出：

```
brute n <= 16 OK; midpoint map checked on 32767 walks; OEIS A189722:16 A336662:17 A337353:17 relations on stored terms: k<=38, n<=39
```

數字 16 可以改小（更快），改大會慢很多（路徑數大約每步乘 1.6）。

## 自己驗

不用程式也能驗：打開 OEIS 上三條條目的數字，照草稿「自己驗一次」那段對幾項。手算：3 步的一直轉彎路徑（第一個轉彎向左）只有「左左」「左右」兩種，乘 2 是 4 = A336662(2)。

## 程式驗不到的

暴力只到 n = 16；對所有 n 成立靠證明裡的中點對應。中點對應本身在 m ≤ 16 逐條檢查過。
