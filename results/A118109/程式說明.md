## l08_rule54_rows.py 每一段在做什麼

- **`DATA_118109`、`DATA_265225`**：2026-11-23 從 OEIS 抄下來的資料，用來對答案。
- **方法 1 `rows_sim`：照規則表模擬。** 每格把（左, 中, 右）看成二進位數 0～7，去查 54 的二進位第幾位是 1。這是「完全照定義」的算法。
- **方法 2 `rows_closed`：直接用證明裡的形狀公式產生每一列。** 偶數列：x ≡ t (mod 4) 亮；奇數列：x ≢ t+1 (mod 4) 亮。兩種方法到 n = 300 每一列都一樣 → 證明裡的「引理」至少在這範圍內沒錯。
- **算 a(n)**：A118109 把一列的 0/1 接起來當十進位數讀；A265225 把每列亮格數一路加起來。
- **逐一檢查公式**（程式裡每一行 `assert` 後面都註明是誰的公式）：Keller 的下取整（Python 的 `//` 就是整數除法取下取整）、Barker 的兩個遞迴、Hurt、Veselovac 的公式。
- **生成函數**：`mul` 是多項式乘法。把數列當成多項式的係數，乘上分母，結果應該只剩分子（A118109 剩 1 + 111x，A265225 剩 1 + 3x，後面全是 0）。這就是「生成函數 = 分子／分母」的意思。
- **Ianakiev 的註解**：對 n = 1 到 11，用 `itertools.combinations` 把「從 1..2n 選 n 個」的所有選法都列出來，找出總和被 n 整除的最小值，檢查它等於 a(n−1) 而不等於 a(n)。

## critic_c_rule54_rows.py 在做什麼

審查員沒有看 l08 的寫法，刻意每一步都換方法：

- 一列存成一個大整數，用位元運算一次算整列：`new = c ^ ((c << 1) | (c >> 1))`，就是「自己 XOR（左 OR 右）」，不查表、不用形狀公式。
- 十進位值用「把每個亮格的 10^i 加起來」算，不是把字串接起來。
- 生成函數用「級數除法」展開分子／分母，而不是乘上分母。
- Ianakiev 的最小和用動態規劃（記錄「選了幾個、和除以 n 的餘數」時的最小和），可以算到 n = 40，比列舉全部選法快很多；兩種讀法（a(n−1)、a(n)）都測。

## 不用程式也能自己驗證

用證明說明裡的表：a(2) = 10001 = 10000 × 1 + 1；a(3) = 1110111 = 10000 × 111 + 111。

下取整公式可以用計算機試：n = 2 時 (10000 × 100²) / 9999 = 100000000 / 9999 = 10001.0001…，取整數部分 10001 = a(2)。

遞迴：a(4) = 10001 × a(2) − 10000 × a(0) = 10001 × 10001 − 10000 = 100020001 − 10000 = 100010001 ✓。
