## l07_a071052_even.py 每一段在做什麼

- **`DATA`**：從 OEIS 抄來的前 67 項，用來對答案。
- **方法 1 `zeros_ca`：直接模擬。** 一列存成串列，兩邊各補兩個 0，然後每格 = 左 `^` 中 `^` 右（`^` 是 XOR）。數 0 的個數 `row.count(0)`。
- **方法 2 `zeros_poly`：多項式。** 把 (1+x+x²)^n mod 2 的係數存成一個整數的二進位位元（第 k 位 = x^k 的係數奇偶）。每次乘以 1+x+x²（二進位 `0b111`），用的是「不進位乘法」：乘法時加法換成 XOR，所以 1+1 = 0，不會進位。這正是 mod 2 的多項式乘法。0 的個數 = 2n+1 − （二進位裡 1 的個數）。
- **主程式：**
  1. 兩種方法到 n = 2000 每一項都一樣。
  2. 前 67 項和 OEIS 一樣。
  3. 對每個 n ≤ 1000：a(2n) = a(n) + 2n。
  4. 逐格檢查：`rows[2n][0::2] == rows[n]`（第 2n 列每隔一格取，等於第 n 列），`rows[2n][1::2]` 全是 0。`[0::2]` 是 Python 的「從第 0 個開始每隔 2 個取一個」。

## critic_c_a071052.py 在做什麼

審查員刻意用完全不同的方法：

- **M1（不模擬）**：(1+x+x²)^n 展開，x^k 的係數是「多項式係數」n!/(a! b! c!) 的總和，其中 a+b+c = n、b+2c = k。它是奇數 ⇔ a、b、c 的二進位沒有重疊的 1（這是 Lucas 定理的推廣，超出高中，可以想成「二進位版的不進位加法」）。程式把 n 二進位裡的每個 1 分給 a、b、c 其中一個，枚舉所有分法。
- **M2**：用字典（位置 → 值）模擬，不固定視窗寬度，並逐格檢查「第 2n 列 = 第 n 列插 0」。
- **M3**：亮格數 A071053 的另一個已知公式（Jacobsthal 數的 run-length transform），只是交叉對照。

三種方法都一致才算過。

## 不用程式也能自己驗證

用格子紙畫規則 150 前 8 列（每格 = 上面三格加起來是奇數就塗黑）：

```
n=3       ■■□■□■■        暗格 2
n=6    ■□■□□□■□□□■□■     暗格 8 = 2 + 6
```

把第 6 列的第 1、3、5、…、13 格抄下來，應該就是第 3 列。也可以檢查 a(8) = a(4) + 8 = 6 + 8 = 14：第 8 列是 ■□□□□□□□■□□□□□□□■，17 格裡 3 個亮，暗格 14。
