## l08_a085588_period.py 每一段在做什麼

- **算 D、m、s**：n 一直除以 2 直到變奇數，除了幾次就是 D，剩下的是 m；s 從 1 開始試，2^s 除以 m 的餘數是 1 或 m−1 就停。
- **方法 A：快速算「走很多步」。** 因為證明說「走 2^j 步 = 隔 2^j 格的規則 150」，要走 k 步時，把 k 寫成二進位，每個 1 對應一次「隔 2^j 格」的操作，很快就能走完上百萬步。用這個方法檢查「走 2^D + P 步 = 走 2^D 步」對 n ≤ 400 的隨機狀態都成立；再找 P 的最小因數 d 使得走 2^D + d 步 = 走 2^D 步，這就是 a(n)。
- **方法 B：最笨的模擬。** 一格一格照規則走，用字典記住每個狀態第一次出現的時間，第一次遇到重複就得到週期。完全不用理論，但週期很大時太慢，所以只在可行的 n（121 個）上比對。
- **和 OEIS 比對**：n ≤ 66 的 DATA 全部一致。
- **原留言**：列出「P 整除 a(n)」不成立的 n，第一個是 4，然後 6, 8, 12, 13, …。

## critic_c_a085588.py 在做什麼

審查員沒看 l08 的程式，用另一種想法：圓圈上的狀態看成一個多項式（第 i 格亮 = 有 x^i 項），走一步 = 乘以 x^(n−1) + 1 + x，而且 x^n 當作 1（繞一圈回來）。走 k 步 = 乘以這個多項式的 k 次方，用「平方再乘」的方法算。不用「走 2^j 步 = 隔 2^j 格」這個捷徑，直接檢查多項式等式。s 也用 OEIS 上 A309786 的另一個公式算，交叉比對。

## 不用程式也能自己驗證

- 手算 n = 5（3 步回到起點）、n = 4（2 步）、n = 7（應該 7 步）。
- 算公式值：n = 7，m = 7，2³ = 8 ≡ 1 (mod 7)，s = 3，P = 7，a(7) = 7 ✓。
- n = 13：查 OEIS 條目 a(13) = 21，自己算 2⁶ = 64 = 5 × 13 − 1，所以 s = 6，P = 63 = 3 × 21 ✓。
