## l06_a268754_odd.py 每一段在做什麼

**`step1`：走一步。** 整條線存成一個整數，第 i 個二進位位元就是第 i+1 格。

```python
((y << 1) ^ (y >> 1)) & ((1 << n) - 1)
```

`y << 1` 是整串往左移一格（每格拿到右鄰居的值）、`y >> 1` 往右移一格（拿到左鄰居的值），`^` 是 XOR，`& ((1<<n)-1)` 把超出 n 格的部分切掉（兩端外面當暗格）。這正是 OEIS 條目自己的 Python 寫法。

**`way1`：找暫態和週期（Brent 演算法）。** 想像兩隻烏龜在同一條路上走，一隻停著、一隻往前走，走的步數每次翻倍才換位置，總會在循環裡相遇；相遇時走的步數就是週期。好處是不用記住所有走過的狀態。

**`way2`：用完全不同的寫法再算一次。** 不用線，而是用一個 2n+2 格的圓圈，從第 1 格和第 2n+1 格（左右對稱）亮出發，規則一樣是 XOR。對稱的圓圈的一半就等於零邊界的線（A334504 偶數寬度用到的同一個想法）。用字典記住每個狀態第一次出現在第幾步，第一次重複就知道週期。

**主程式檢查的事情：**

1. 對 n = 1 到 40，`way1` 和 `way2` 算出的（暫態, 週期）一樣（長度 n 和 2n+1 都檢查）。
2. 公式：n+1 不是 2 的次方時，長度 2n+1 的週期 = 2 × 長度 n 的週期；是 2 的次方時兩個都是 1。`(n + 1) & n == 0` 是判斷「n+1 是 2 的次方」的小技巧（2 的次方的二進位只有一個 1，減 1 後全部錯開）。
3. 和 OEIS 前 54 項比對（程式開頭的 `OEIS = [...]`）。
4. **攤開引理**（n ≤ 30）：長線第 2t+1 步 = 把短線第 t 步的第 i 位搬到第 2i+1 位。`spread` 函數就是做這個搬移。
5. **全滅**（n ≤ 2000）：走 n+1 步內會不會變成 0，答案要剛好是「n+1 是 2 的次方」。

## critic_c_a268754.py 在做什麼（第三種方法，跑比較久，要幾分鐘）

這支是審查員寫的，刻意**不模擬一步一步走**，而是直接用公式算出第 t 步的狀態：規則 90 從一格出發的圖案是巴斯卡三角形 mod 2，所以第 t 步某格的值可以用組合數 C(t, k) 的奇偶算出來（再把圓圈繞回來的「鏡像」加總）。C(t, k) 是不是奇數，用 Lucas 定理的判斷法 `k & ~t == 0`（k 的二進位 1 都要落在 t 是 1 的位置）。

然後它不「找」週期，而是「驗證」候選週期 p（從 OEIS 資料或公式來）：

- 第 T+p 步要等於第 T 步（p 確實是週期）；
- 對 p 的每個質因數 q，第 T+p/q 步都不等於第 T 步（p 是最小的週期，因為最小週期一定整除任何週期）。

這和 l06 的「一步一步走、找重複」完全不同，兩種方法都同意，才比較放心。

## 不用程式也能自己驗證

拿格子紙算：

- n = 2：■□ → □■ → ■□，週期 2。n = 5：週期 4 = 2 × 2（見證明說明裡的表）。
- n = 4：週期應該是 6；n = 9 應該是 12 = 2 × 6。
- n = 3、7：會全滅（n+1 = 4、8）。n = 3：■□□ → □■□ → ■□■ → □□□。

OEIS 上前幾項：1, 2, 1, 6, 4, 14, 1, 14, 12, 62，你可以自己檢查 a(3) = 1、a(5) = 2·a(2) = 4、a(7) = 1、a(9) = 2·a(4) = 12。
