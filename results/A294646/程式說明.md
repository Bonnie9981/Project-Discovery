# A294646 程式說明（高二版）

## 這些程式在算什麼

| 檔案 | 語言 | 做什麼 |
|---|---|---|
| `code/verify.py` | Python | 直接驗證反例 n = 9814447404，並檢查定義和 OEIS 前 20 項一致 |
| `code/brute.c` | C | 最笨的搜尋：一個一個奇數 m 檢查三種情況 |
| `code/gen_primes.py` + `code/scan.c` | Python + C | 聰明的搜尋：先列出「可行的質數」，再只檢查 m = p × k 的形式 |

## 最重要的一支：verify.py（你自己一定可以跑）

只要裝 Python 3.8 以上（python.org，安裝時勾「Add Python to PATH」），不需要其他東西：

```
python results\A294646\code\verify.py
```

應該印出：

```
n = 9814447404  2n+1 = 19628894809 = 367 * 53484727
a(n) = 19628894806  2n-2 = 19628894806  equal: True
(3*2^(2n)+1) mod (2n+1) = 0
first 20 DATA terms match
```

**程式在做什麼（逐行）：**

- `assert m == 367 * 53484727`：檢查 m 真的等於這兩個數相乘。
- `x = pow(2, 2 * n, m)`：算 2^(2n) 除以 m 的餘數。Python 的 `pow` 有三個參數時就是用「快速冪」，邊乘邊取餘數，所以一瞬間就算完。
- `a = pow(x, -1, m)`：算 x 在 mod m 下的倒數（模反元素），也就是 a(n) 的定義。
- 印出 a 是否等於 2n−2，以及 3 × 2^(2n) + 1 除以 m 的餘數（應該是 0）。
- 最後用同樣的定義算 n = 1 到 20，和 OEIS 前 20 項比對，確認我們對定義的理解沒錯。

**你可以自己再加一步驗證：** 在 Python 裡輸入 `367 * 53484727`，看是不是 19628894809；輸入 `pow(2, 8, 9)` 應該得 4，`pow(4, -1, 9)` 應該得 7（就是證明說明裡的 a(4) = 7）。

## 搜尋程式（要 C 編譯器，Windows 上比較麻煩，可以只看說明）

**brute.c：** 對範圍內每個奇數 m，算 x = 2^(m−1) 除以 m 的餘數（自己寫的快速冪 `pm`），然後檢查三件事：3x + 1 能不能被 m 整除（2n−2 的情況）、x + 1 能不能被 m 整除（2n 的情況）、2x 除以 m 是不是餘 1（2 的情況）。找到就印出來。跑法（Linux / Mac）：`gcc -O2 -o brute brute.c` 然後 `./brute 3 19640000000`。範圍到 1.964 × 10^10，只找到我們那個 m。

**gen_primes.py + scan.c：** 先用 Python（需要 sympy 套件）列出 2,000,000 以下所有「可行的質數」p，以及 m/p 必須滿足的餘數條件，存到 plist.txt；scan.c 再對每個 p，只檢查符合條件的 k（m = p × k，k ≤ 10^9）。這樣可以搜到 6.1 × 10^10，比 brute 遠很多。

**critic_search.go：** 審查員不看我們的程式，自己用 Go 語言寫：自己的質數表、從高位開始的快速冪（和我們的方向相反）、三種搜尋（結構搜尋到 6.1 × 10^10、不假設 mod 6 條件的一般搜尋到 10^10、窮舉到 2 × 10^8），結果一致。

**測試搜尋邏輯有沒有漏：** 把「3」換成「15」，聰明搜尋找到 987677 和 1589597，最笨的窮舉也找到同樣兩個，表示縮小範圍的推理沒有誤刪答案。

## 不用程式也能自己驗證

用計算機或 Python 驗算小的 n：

- n = 4：m = 9，2^8 = 256，256 ÷ 9 餘 4；4 × 7 = 28，28 ÷ 9 餘 1，所以 a(4) = 7。
- n = 7：m = 15，2^14 = 16384，16384 ÷ 15 餘 4；4 × 4 = 16 餘 1，所以 a(7) = 4（OEIS 第 7 項是 4）。
