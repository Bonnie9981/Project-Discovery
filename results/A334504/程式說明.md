## l01_check.py 每一段在做什麼

**模擬規則 26。** 程式把一圈格子存成一串 0 和 1。更新時，每格把（左, 中, 右）看成一個三位二進位數 4×左 + 2×中 + 右（0 到 7），再去看 26 的二進位第幾位是 1。這一行就是規則表：

```python
(rule >> (4 * cells[i - 1] + 2 * cells[i] + cells[(i + 1) % w])) & 1
```

`>>` 是二進位往右移，`& 1` 是取最後一位。`% w` 是除以 w 的餘數，讓最右邊那格的右鄰居繞回格子 0。

**兩種獨立的方法（Way 1、Way 2）。** 好的檢查要用兩種不同寫法算同一件事，避免同一個 bug 讓兩邊一起錯。

- Way 1：用 repo 裡另一支模擬器 `research/r002/impl_b.py`（把整圈存成一個整數，每格是一個二進位位元），每一步都和「巴斯卡窗口公式」`closed_form` 比對，一格都不能差。再用「Brent 演算法」（一種找循環的方法，像兩個人在環形跑道上一快一慢跑，總會相遇）找暫態和週期，要等於 (0, w × 2^k)。
- Way 2：自己重寫一個最簡單的模擬（用串列），從起點一直走到 3 個週期那麼遠，記下所有回到起點的時刻，要剛好等於「w 和 2^k 都整除 t」的那些 t。

**Lemma 2（Lucas 推論）。** 用 Python 內建的 `math.comb`（就是組合數 C(n, k)）直接算，對 t ≤ 2000 檢查兩件事：t 是 2^m 的倍數時 C(t, 1) … C(t, 2^m − 1) 都是偶數；以及 C(t, 2^v) 是奇數（2^v 是整除 t 的最大 2 的次方）。這部分完全不碰格子，是獨立的數學檢查。

**Lemma 3（一步更新）。** 直接檢查證明裡那四種情況：把巴斯卡窗口的三格代進規則 26，結果要等於下一步的窗口。對每個位置、t ≤ 64 全部試過。

**偶數寬度順便檢查。** 對偶數 w ≤ 40，檢查整個過程中都沒有兩格相鄰都亮，而且規則 26 和規則 90 的週期一樣。

## l02_check.py 每一段在做什麼

- `null90`：規則 90 在一條線上、兩端外面當作暗格（「null boundary」）。每格新值 = 左鄰 XOR 右鄰（`^` 就是 XOR）。
- `way2`：從線的左端一格亮出發，一直走，用一個字典記住「這個狀態第一次在第幾步出現」，第一次遇到重複的狀態就知道暫態和週期。
- 主程式：對 n = 1 到 40，圓圈寬 w = 2n+2，檢查「圓圈週期 = 線的週期」、「圓圈暫態 = 線的暫態 + 1」，而且線的週期要等於從 OEIS 抄來的 A268754 前 54 項（程式開頭那串數字，2026-11-22 從條目抄的）。
- `structure`：n ≤ 20 時，逐步檢查證明說的形狀：格子 0 和格子 m 都暗、格子 1 到 m−1 正好是那條線、另外半圈是鏡像。

## 不用程式也能自己驗證

拿一張格子紙：

1. w = 3：從 ■□□ 開始照規則 26 的表算，應該第 6 步回到 ■□□（3 × 2 = 6）。
2. w = 5：算到第 20 步回到 ■□□□□（5 × 4 = 20）。中間第 5 步應該是 ■□■□□。
3. w = 6：應該看到格子 0 和格子 3 一直暗，左右對稱，週期 2。

跑出來的結果（我們在雲端跑過）：寬度 3 到 12 的（暫態, 週期）依序是 (0,6)、(2,1)、(0,20)、(1,2)、(0,28)、(4,1)、(0,72)、(1,6)、(0,88)、(2,4)。奇數那些全部是 w × 2^⌊log₂ w⌋。
